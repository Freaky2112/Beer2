# 🍺 Beer Journal

A self-hosted, multi-user beer tasting journal built with Flask, MariaDB and Docker Compose. Responsive dark craft-beer UI, English/French interface, personal reviews and CSV export.

## Features

- Multiple accounts; each user sees and manages only their own beers, breweries and wishlist.
- Beer reviews: brewery, style, ABV, IBU, serving temperature, date tasted, tasting notes and photo.
- Ratings from 0 to 10 in **0.5-point increments**.
- Comma-separated flavour tags (created automatically), searchable and filterable.
- Brewery directory with location, country, website and notes.
- Beer wishlist.
- Rating/style charts and top brewery statistics.
- CSV export of reviews.
- English/French language toggle.
- Image uploads stored in a persistent Docker volume (10 MB limit; images are re-encoded to JPEG).

## Quick start (Linux)

```bash
unzip beer-journal.zip
cd beer-journal
cp .env.example .env
nano .env
```

Change **DB_PASSWORD**, **DB_ROOT_PASSWORD** and **SECRET_KEY** to long, unique random values. Then start:

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f web
```

Open `http://YOUR-SERVER-IP:8088` (or the port you selected in `.env`) and sign in with the initial administrator credentials configured in `.env`. Additional accounts can only be created using invitation links generated by an administrator.

Generate a strong secret with:

```bash
openssl rand -hex 32
```

## Backups

The database and photos are stored in named Docker volumes. Back up both:

```bash
docker compose exec -T db mariadb-dump -u"$DB_USER" -p"$DB_PASSWORD" "$DB_NAME" > beerjournal.sql
docker run --rm -v beer-journal_beer_uploads:/data -v "$PWD":/backup alpine \
  tar czf /backup/beer-uploads.tar.gz -C /data .
```

Compose volume names may be prefixed by your project directory. Check with `docker volume ls`.

Restore the SQL dump into the database and restore the uploads archive into the uploads volume. Keep the `.env` file backed up securely.

## Updating

```bash
docker compose pull
docker compose up -d --build
```

Back up first. The application creates missing tables automatically on startup. For future schema changes, add a migration system before upgrading a production instance.

## Reverse proxy

The app listens on port 5000 inside Docker and publishes `${APP_PORT}` (default 8088). Put it behind your existing reverse proxy (Traefik, Nginx Proxy Manager, etc.) and enable HTTPS. For Traefik, the web service/container port is **5000**. Do not expose MariaDB's port to the internet.

## Security notes

- Set unique secrets before first start; do not commit `.env`.
- Registration is invitation-only. Administrators generate single-use invitation links that expire after 7 days.
- Use HTTPS when accessing it outside your LAN.
- Uploads require login; the app checks image content and re-encodes uploads.
- Each user's records are scoped to their account. This is a personal journal, not a public review-sharing platform.
- The first version uses `db.create_all()` for simple setup. Back up before upgrades and use Alembic/Flask-Migrate for long-term schema evolution.

## Stack

- Python 3.12 / Flask
- Flask-Login + Werkzeug password hashing
- Flask-WTF CSRF protection
- Flask-SQLAlchemy + PyMySQL
- MariaDB 11.4
- Bootstrap 5.3 and Chart.js (CDN)
- Docker Compose

## Troubleshooting

```bash
docker compose logs -f web
docker compose logs -f db
docker compose restart web
```

If the web container cannot connect to MariaDB, wait for the database healthcheck and inspect the DB logs. If the page is unreachable, check the Linux firewall and that `${APP_PORT}` is published.


## Invitation-only registration

Public registration is disabled. Administrators generate single-use invitation links from the Admin page; links expire after 7 days and can be revoked. Only a SHA-256 token hash is stored.

On a fresh database, set ADMIN_USERNAME, ADMIN_EMAIL and ADMIN_PASSWORD (12+ characters) in .env before first start. On an existing database, startup adds the is_admin column without deleting existing rows and promotes the earliest existing user only if no admin exists. Existing reviews, breweries, wishlist records and photo volume are preserved. Do not use `docker compose down -v` for this update.

Update with `docker compose up -d --build web` after replacing the project files. The Compose file passes the three `ADMIN_*` variables into the web container. Confirm they are present in `.env` in the same directory as `docker-compose.yml`. Do not run `docker compose down -v`; that deletes your database volume.
